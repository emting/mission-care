# 尚待教會決策與核准（全部未核准）

**本文件不是核准紀錄。所有項目目前均為「未核准／待教會決策」。** Mission Care 是使用虛構資料的提案 MVP，沒有代表教會、宣教士、財務或法務表示同意，也不可據此啟用正式服務。程式預設或種子設定只是技術示範，不構成治理決策。

來源：主 PRD §17、管理者規格 §18。下列「建議決策單位」只是提案，不表示已任命。任何核准須另留具名責任人、日期、適用範圍、有效期限與文件連結；本次沒有填入任何核准人或日期。

## 主 PRD §17

| 狀態 | 待決項目 | 應提供的決策／證據 | 建議決策單位（未任命） |
| --- | --- | --- | --- |
| 未核准 | 教會正式授權、業務主管、安全核准人 | 書面專案授權、責任歸屬、升級／停機權限；確認提案可否進入試點 | 教會治理與宣教主管 |
| 未核准 | 宣教士及當事人授權、真實範圍、公開級別 | 逐位同意、代表權核對、A/B/C 分類、照片／原稿範圍、撤回方式；高風險不上線名單不得收集詳細內容 | 宣教主管、安全責任人、當事人／合法代表 |
| 未核准 | LINE 官方帳號與 Provider 所有權 | 教會持有 OA／LINE Login channel／LIFF／Messaging channel 的證明、管理交接與金鑰保管；測試與正式隔離 | 教會數位系統及宣教主管 |
| 未核准 | 個資法、資料處理委託、跨境 AI、保留政策 | 法律依據、隱私告知、委外契約與資料位置、外部 AI 可否使用、保存／刪除／備份與當事人權利流程 | 教會、法務／個資責任人 |
| 未核准 | 官方奉獻入口及個別宣教士指定認定 | 官方網域與連結、是否得指定對象、收據／用途責任及雙人異動核准流程；平台不處理款項 | 財務與宣教主管 |
| 未核准 | 測試資料集、預算上限、正式上線門檻 | 核准試點範圍、僅虛構資料到何時、LINE／儲存／維運費用上限、測試證據與 go/no-go 簽核 | 專案負責人、財務、安全核准人 |

## 管理者規格 §18

| 狀態 | 待決項目 | 應提供的決策／證據 | 建議決策單位（未任命） |
| --- | --- | --- | --- |
| 未核准 | 專案責任人、角色名冊、互相覆核配置 | 具名角色 × 宣教士範圍、任期、撤職／代理、不同作者／編輯與覆核人配置、定期權限回顧 | 教會治理、宣教主管 |
| 未核准 | 管理員登入與 MFA 恢復 | 是否採納目前自架 scrypt＋TOTP 提案、啟用／停權程序、遺失裝置身分重驗、恢復核准與憑證輪替；不得把恢復當 MFA 後門 | 數位系統、安全責任人 |
| 未核准 | 完全不上系統資訊、公開／照片／當事人授權政策 | C 級判定與獨立安全渠道；A/B 可保存／可顯示欄位；逐版同意及背景地點／臉孔檢視標準 | 宣教主管、安全責任人、當事人 |
| 未核准 | 會友核對、授權期限、匿名統計與保留期 | 教會既有身分核對方式、逐位 grant 期限與撤銷、最小群體統計門檻、互動／原稿／帳號資料保留與刪除 SLA | 宣教主管、個資責任人 |
| 未核准 | 奉獻連結與財務角色 | 具名不同提案／核准人、官方入口白名單、停用與異動稽核；雙人控制不得以共用帳號替代 | 財務主管 |
| 未核准 | 稽核儲存、事故通報、正式批准 | 稽核與備份位置、最小讀取權限與保留期、獨立不可竄改儲存、事故聯絡／通知時限、lockdown／復原演練及正式上線簽核 | 安全、維運、個資與教會治理 |
| 未核准 | 預算、供應商、既有系統整合 | 維運人力與費用、服務供應商與契約、備援／移轉方案、是否整合既有教會系統及最小交換欄位；不得假定既有帳號自動獲權 | 專案負責人、數位系統與財務 |

## 在取得核准前的界線

- 不匯入真實人名、地點、原稿、照片、LINE subject 或正式帳密；種子帳號與 TOTP 僅可本機試用。
- 不把 CI 通過、示範用同意旗標、雙人測試帳號或 GitHub push 視為任何人的同意／上線核准。
- 通知預設暫停且配額零；外部 AI 未啟用；奉獻入口未啟用。不得為了展示功能繞過授權、審查、正式環境或安全門檻。
- 正式發布前，逐項留下核准證據並處理 [威脅模型](threat-model.md) 的殘餘風險；測試、備份還原、金鑰輪替、事故演練與隱私刪除履行亦須有可查證紀錄。
